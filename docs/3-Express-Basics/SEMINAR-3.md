# Тема 3. Семинар: свой сервер вместо мока

> **Организационное примечание.** Семинар и лекция по этой теме проходят в один день, порядок может отличаться. Материал здесь новый, поэтому в каждом задании указано, в каком разделе лекции ([LECTURE-3.md](LECTURE-3.md)) лежит нужный образец кода, — если семинар у тебя идёт первым, открывай лекцию прямо по ходу работы.

**Перед началом.** Устанавливать ничего не нужно, но одну вещь надо проверить прямо сейчас. Открой терминал и выполни:

```bash
node --version
```

Если версия младше 22.18 — обнови Node с [nodejs.org](https://nodejs.org/), взяв сборку с пометкой LTS. На старой версии сервер из этой темы просто не запустится: Node не умеет выполнять `.ts`-файлы напрямую и ответит ошибкой про неизвестное расширение.

С этой темы у тебя в работе будет **два терминала сразу**: один занят клиентом, другой — сервером. Второй открывается кнопкой «+» на панели терминала VS Code, и в каждом надо сначала перейти в нужную папку — `cd client` или `cd server`.

**Дедлайн сдачи семинара:** первое занятие Темы 5.

## Задание 1 (промежуточное). Свой сервер на Express

**Навык:** заведение серверного проекта с нуля, роутинг.
**Ветка:** `feature/server-setup`.

Папка `server/` в репозитории пустая — в ней нет даже `package.json`. Задача: сделать так, чтобы в ней заработал сервер, отдающий карточки. Образцы кода — в лекции, разделы «Заводим проект сервера» и «Роутинг».

1. Создай ветку `feature/server-setup` от `main`.
2. Заведи проект: `cd server`, `npm init -y`, добавь в получившийся `package.json` строку `"type": "module"` и скрипт `"dev": "node --watch index.ts"`.
3. Поставь зависимости: `express` — обычной, `typescript`, `@types/node` и `@types/express` — с флагом `--save-dev`. Положи рядом `tsconfig.json` из лекции.
4. Напиши `server/index.ts`: создай приложение, подними его на порту 3001 с сообщением в консоль и заведи один роут — `GET /cards`, отдающий массив из трёх карточек. Возьми те же три карточки, что лежат в `client/db.json`.
5. Запусти `npm run dev` из `server/` и открой `http://localhost:3001/cards` в браузере.

**Готово, когда:**

- [ ] `npm run dev` из папки `server/` запускает сервер, и в терминале видно сообщение с адресом;
- [ ] `http://localhost:3001/cards` в браузере показывает JSON с тремя карточками;
- [ ] если поменять текст карточки в `index.ts` и сохранить файл, сервер перезапустится сам — в терминале это видно, а страница после обновления показывает новый текст;
- [ ] в `server/` лежат `index.ts`, `package.json` и `tsconfig.json`;
- [ ] папки `node_modules` нет среди изменений в панели Source Control — она не должна попадать в коммиты;
- [ ] в ветке `feature/server-setup` минимум два коммита: заведение проекта и код сервера.

> [!TIP] Совет
> Если браузер по адресу `http://localhost:3001/cards` показывает ошибку «не удаётся установить соединение» — сервер не запущен или упал. Смотри терминал, где выполнялся `npm run dev`: текст ошибки будет там, а не в браузере. Это общее правило на весь курс — ошибки сервера живут в терминале сервера.

## Задание 2 (промежуточное). Мок в отставку

**Навык:** `express.json()`, чтение тела запроса, статус-коды.
**Ветка:** `feature/real-api`.

Сначала Git: влей `feature/server-setup` в `main` своей копии, переключись на `main`, нажми «Sync Changes» и создай от него ветку `feature/real-api`.

До сих пор данные доске отдавал мок-сервер — тот самый `npm run server`, который ты запускал в семинарах тем 1 и 2. В этой теме ты его ещё ни разу не запускал и не запустишь: порт 3001 уже занят твоим собственным сервером из задания 1, а двум программам один порт не достанется.

Сейчас и выяснится, чего стоил весь разговор про правильно устроенный мок: чтобы клиент заговорил с твоим сервером вместо мока, в клиенте **не нужно менять ни строчки**. Он как стучался на `/api/cards`, так и стучится — просто на том конце теперь другая программа. Образцы кода — в лекции, разделы «Middleware» и «Тело запроса и ответ».

1. Убедись, что твой сервер работает: `npm run dev` из `server/`. Мок при этом не запускай — он больше не понадобится.
2. В другом терминале запусти клиент (`npm run dev` из `client/`) и открой доску. Карточки на ней теперь приходят из твоего `index.ts` — чтобы убедиться наверняка, поменяй в нём заголовок одной карточки и обнови страницу в браузере.
3. Подключи `express.json()` и добавь роут `POST /cards`: он читает `title` из тела запроса, создаёт карточку с новым `id`, отвечает статусом `201` и созданной карточкой.
4. Закрой пустой ввод на сервере: если `title` пустой или состоит из одних пробелов — ответь статусом `400` и JSON с описанием ошибки, карточку не создавай.
5. Проверь через форму на доске: обычное название создаёт карточку, а пустое — нет.
6. Мок больше не нужен — удали `client/db.json` и скрипт `"server"` из `client/package.json`. Отдельным коммитом.

> [!WARNING]
> Данные сервера живут в обычной переменной, а `--watch` перезапускает сервер при каждом сохранении файла. Значит, все карточки, добавленные через форму, при перезапуске исчезают, и на доске снова остаются исходные три. Это не поломка и чинить это сейчас не нужно — настоящее хранилище появится в теме 5. Но знать об этом надо, иначе полчаса уйдёт на поиск несуществующего бага.

> [!IMPORTANT] Напоминание
> Проверку на пустой `title` ты уже писал — в теме 2, в задании про защиту от пустой карточки. Тогда её делал клиент, сейчас то же самое делает сервер, и убирать клиентскую проверку не нужно: они защищают от разного. Почему — в лекции, врезка после `POST /cards`.

**Готово, когда:**

- [ ] доска показывает карточки из `server/index.ts` — поменяй в нём заголовок карточки, обнови страницу, и текст на доске изменится;
- [ ] в коде клиента нет ни одного изменения — сравни ветку с `main` в панели Source Control: файлы из `client/src/` там не появлялись;
- [ ] форма на доске создаёт карточку, и она приходит с сервера с непустым `id`;
- [ ] пустое название карточку не создаёт, а сервер отвечает статусом `400`;
- [ ] `client/db.json` удалён, скрипта `"server"` в `client/package.json` больше нет;
- [ ] в ветке отдельные коммиты на `POST /cards`, на проверку пустого названия и на удаление мока.

## Задание 3 (оценочное). Тикет KAN-3

Теперь — задача целиком по конвейеру из темы 2: разведка, постановка (`proposal.md` и спека), `design.md` и `tasks.md`, реализация по шагам, архивация. Предмет тот же, что и в теме 2, только теперь это не React-компонент, а Express-роут.

> [!IMPORTANT] Проверь перед началом
> Это задание — серверная половина той работы, клиентскую половину которой ты сделал в оценочном задании темы 2 (тикет KAN-2). Оно предполагает, что на доске уже есть кнопка удаления, а в `client/src/api/cards.ts` — функция `deleteCard`, отправляющая запрос на сервер.
>
> Поэтому **зачесть KAN-3 без закрытой темы 2 нельзя**: удалять с доски будет нечем, и проверять на приёмке — нечего. Если оценочное задание темы 2 у тебя ещё не сдано или возвращено на доработку, закрой сначала его — даже если его собственный дедлайн ещё не наступил.

Влей `feature/real-api` в `main` своей копии и создай ветку `feature/delete-card-api`.

> **KAN-3: После переезда на свой сервер сломалось удаление карточек**
>
> Кнопка удаления на доске работала, пока данные отдавал мок. Сейчас она не работает: карточка не удаляется, а в консоли браузера видно, что сервер отвечает `404`. Вдобавок в ответ приходит HTML-страница с текстом ошибки — клиент ждёт JSON и не может показать пользователю ничего внятного.
>
> **Критерии приёмки:**
>
> 1. Удаление карточки работает с доски: карточка исчезает и не возвращается после обновления страницы (`F5`);
> 2. Идентификатор удаляемой карточки сервер берёт из пути запроса, а не из тела;
> 3. Попытка удалить несуществующую карточку не роняет сервер: в ответ уходит `404` и JSON с описанием;
> 4. Запрос на любой неизвестный адрес получает в ответ JSON со статусом `404`, а не HTML-страницу Express;
> 5. В приложении есть обработчик неожиданных ошибок, отвечающий статусом `500`, — зарегистрированный так, чтобы он действительно срабатывал;
> 6. Код клиента не изменён.

Образцы — в лекции, разделы «Роутинг» (определение пути с параметром) и «Обработка ошибок». Какой именно статус-код возвращать при успешном удалении — реши сам и зафиксируй решение в спеке изменения: это ровно тот случай, когда тикет не отвечает на вопрос, а исполнителю нужно ответить на него явно, а не по ходу дела.

> [!NOTE]
> Критерий 6 — не формальность, а проверка главной мысли темы. Если для работы удаления пришлось править `client/`, значит, сервер отвечает не так, как клиент уже умеет спрашивать, — чини сервер, а не клиент. Посмотреть, чего именно ждёт клиент, можно в `client/src/api/cards.ts`: функция удаления там появилась ещё в теме 2.

Пройди все пять навыков по порядку, как в задании 3 темы 2: разведка → постановка (`proposal.md` и спека) → решение (`design.md` и `tasks.md`) → реализация по шагам с ревью каждого диффа → архивация. Изменение назови `delete-card-api` — заводит его агент скиллом `openspec-new-change`.

**Готово, когда:**

- [ ] удаление карточки работает с доски и переживает обновление страницы;
- [ ] в `client/` нет изменений — ни одного файла в диффе ветки;
- [ ] запрос на несуществующий адрес возвращает JSON с `404` (проверить проще всего в браузере: открой `http://localhost:3001/нет-такого-пути`);
- [ ] удаление несуществующей карточки отвечает `404` и не роняет сервер — после такого запроса доска продолжает работать;
- [ ] обработчик ошибок с четырьмя параметрами зарегистрирован после всех роутов;
- [ ] в `openspec/changes/archive/<дата>-delete-card-api/` лежат все пять файлов: `proposal.md`, спека, `design.md`, `tasks.md`, `report.md`;
- [ ] выбранный статус-код успешного удаления зафиксирован требованием спеки, а не появился по ходу написания кода;
- [ ] история коммитов читается как постановка → решение → шаги реализации → архивация;
- [ ] ветка отправлена в твою копию, открыт merge request с описанием: что сделано и как проверить.

**Сдача:** merge request из `feature/delete-card-api` в `main` твоей копии — **не вливай его сам**, его проверяет преподаватель. Приёмка — по зачётной системе курса: все критерии выполнены → зачтено, иначе замечания в MR и доработка до дедлайна (подробнее — в [«Организации работы»](../COURSE-SETUP.md)).

## Частые ошибки — проверь себя перед сдачей

- `express.json()` подключён после роутов — тело запроса до них не доезжает, `req.body` оказывается `undefined`;
- Обработчик неизвестных путей зарегистрирован до роутов — он перехватывает вообще все запросы, и рабочие эндпоинты перестают отвечать;
- Error-middleware написан с тремя параметрами вместо четырёх — Express не считает его обработчиком ошибок, и тот молча не срабатывает;
- Забыт `next()` в своём middleware — запрос зависает без ответа и без ошибки;
- Карточка «не удалилась», хотя код верный, — проверь, не перезапустился ли сервер: данные в памяти сбрасываются к исходным трём;
- Клиент правился, чтобы удаление заработало, — по тикету он меняться не должен, а изменения в `client/` сразу видны в диффе;
- `node_modules` из `server/` попала в коммит;
- Порт 3001 занят — сервер падает с `EADDRINUSE`: чаще всего он уже работает в другом терминале, про который ты забыл, и запускается второй раз. Найди тот терминал и останови сервер в нём (`Ctrl+C`);
- Один гигантский коммит на всю задачу вместо последовательности постановка → решение → шаги → архивация;
- Merge request оценочного задания по ошибке открыт в репозиторий курса, а не в свою копию (та же ловушка форка на GitHub, что и в темах 1–2).
