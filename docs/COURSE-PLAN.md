### Входные знания студентов (уже пройдено, не повторяем)

- **TypeScript**: базовая типизация, базовые дженерики — сложные конструкции (conditional/mapped types и т.п.) в курс не включаем, это неэффективно на данном уровне
- **React**: состояние, хуки, библиотеки компонентов, CSS-модули, React Query — базовый уровень уже есть, курс даёт архитектурный слой поверх этого
- **Сборка**: Vite в режиме `npm run dev` уже знаком — курс добавляет только `npm run build` и упаковку в контейнер, без более сложных инструментов сборки

### Вес в итоговой оценке

| Компонент                                          | Вес |
| --------------------------------------------------- | --- |
| Семинары (зачёты оценочных заданий + тесты по темам) | 35% |
| Домашнее задание (2 этапа)                           | 40% |
| Экзамен                                              | 25% |

### Как считается итоговая оценка (100-балльная)

Итоговая оценка — сумма трёх компонентов: **Семинары (до 40 баллов) + ДЗ (до 35 баллов) + Экзамен (до 25 баллов)**.

- **Экзамен** — оценивается в баллах 0–100 и идёт в итог с весом 0,25 (до 25 итоговых баллов);
- **ДЗ** — каждый из двух этапов оценивается 0–100, среднее этапов идёт в итог с весом 0,35 (до 35 итоговых баллов);
- **Семинары** — считаются по темам. Каждая из 8 тем «стоит» ровно **5 итоговых баллов** и складывается из двух равных частей:
  - **зачёт оценочного задания** — 2,5 балла (бинарно: зачтено — балл начисляется целиком, не зачтено — 0);
  - **тест по теме** — до 2,5 балла, пропорционально доле правильных ответов (независимо от числа вопросов в тесте).

Шпаргалка для студента — сколько приносит одна тема:

| Сделано в теме                     | Баллы к итоговой оценке |
| ---------------------------------- | ----------------------- |
| Зачёт оценочного задания           | 2,5                     |
| Тест (при 100% правильных ответов) | до 2,5                  |
| **Тема закрыта целиком**           | **5**                   |
| **Все 8 тем целиком**              | **40**                  |

Пример расчёта: 6 зачётов (6 × 2,5 = 15) + средний результат тестов 70% (8 × 2,5 × 0,70 = 14) → Семинары = 29 баллов. Этапы ДЗ — 85 и 75 → среднее 80, с весом 0,35 → 28 баллов. Экзамен — 60, с весом 0,25 → 15 баллов. Итог: 29 + 28 + 15 = **72 балла из 100**.

## 2. Календарь на 16 суббот

Занятия идут раз в неделю по субботам. Каждая тема занимает 2 субботы подряд (без разрыва между темами — вторая суббота одной темы предшествует первой субботе следующей).

| Суббота | Содержание                                                                                                  |
| ------- | ------------------------------------------------------------------------------------------------------------ |
| 1       | Тема 1: Лекция + Семинар 1                                                                                    |
| 2       | Тема 1: Семинар 2 (оценочное задание)                                                                         |
| 3       | Тема 2: Лекция (+ тест по теме 1) + Семинар 1                                                                 |
| 4       | Тема 2: Семинар 2 (оценочное задание)                                                                         |
| 5       | Тема 3: Лекция (+ тест по теме 2) + Семинар 1                                                                 |
| 6       | Тема 3: Семинар 2 (оценочное задание)                                                                         |
| 7       | Тема 4: Лекция (+ тест по теме 3) + Семинар 1                                                                 |
| 8       | Тема 4: Семинар 2 (оценочное задание)                                                                         |
| 9       | Тема 5: Лекция (+ тест по теме 4) + Семинар 1                                                                 |
| 10      | Тема 5: Семинар 2 (оценочное задание) — контрольная точка ДЗ (этап 1)                                                |
| 11      | Тема 6: Лекция (+ тест по теме 5) + Семинар 1                                                                 |
| 12      | Тема 6: Семинар 2 (оценочное задание)                                                                         |
| 13      | Тема 7: Лекция (+ тест по теме 6) + Семинар 1                                                                 |
| 14      | Тема 7: Семинар 2 (оценочное задание) — выдаётся этап 2 ДЗ                                                         |
| 15      | Тема 8: Лекция (+ тест по теме 7) + Семинар 1                                                                 |
| 16      | Тема 8: Семинар 2 (тест по теме 8 + оценочное задание — сборка и Docker-упаковка) — далее экзамен отдельной датой, сдача этапа 2 ДЗ — через 1–2 недели после этого |

> Логика теста сохраняется: тест по теме N даётся в начале лекционного дня темы N+1. Тест по теме 8 — в начале второго семинара темы 8 (перед итоговым заданием), так как лекции после неё уже не будет.

> Экзамен проводится отдельной датой после 16-й субботы (не входит в цикл тем), с предэкзаменационной консультацией на предшествующей неделе.

## 3. Список тем

1. **Повторение + разделение клиентского и серверного состояния** — быстрый recap того, что было в прошлом семестре (hooks, React Query, CSS-модули), и поверх этого — Zustand: зачем нужен явный клиентский стейт отдельно от серверного (который уже живёт в React Query), как их не путать и не дублировать. Материалы: [лекция](1-React-Flashback/LECTURE-1.md) · [семинар](1-React-Flashback/SEMINAR-1.md).
2. **Работа с AI-агентами в разработке** — раннее и намеренно отдельное занятие: Spec Driven Development как конвейер из пяти навыков работы с агентом по тикету (разведка → постановка → решение → реализация → архивация; конвейер держит инструмент OpenSpec, документы генерирует агент, студент проверяет и решает — агент подключается расширением GigaCode для VS Code, метод не привязан к инструменту), промпт-инжиниринг для кода, ревью AI-сгенерированного кода. Цель — чтобы дальше по курсу студенты параллельно и уже как бы между делом нарабатывали этот навык на каждой теме, не превращая его в отдельную сквозную «новую» тему каждый раз. Материалы: [лекция](2-AI-Agents/LECTURE-2.md) · [семинар](2-AI-Agents/SEMINAR-2.md).
3. **Backend на Node.js/Express + TypeScript, часть 1: основы** — структура Express-приложения, роутинг, middleware, работа с телом запроса/ответом, обработка ошибок на базовом уровне (пока без БД, на моках/in-memory данных). Репозиторий заранее разделён на независимые `client/` и `server/`, каждый со своим `package.json`; в этой теме студент с нуля заводит серверный проект и наполняет `server/`. Материалы: [лекция](3-Express-Basics/LECTURE-3.md) · [семинар](3-Express-Basics/SEMINAR-3.md).
4. **Backend на Node.js/Express + TypeScript, часть 2: архитектура** — слоистая организация (роуты/контроллеры/сервисы), валидация входных данных, разделение ответственности, подготовка API к работе с реальной БД. Материалы: [лекция](4-Express-Architecture/LECTURE-4.md) · [семинар](4-Express-Architecture/SEMINAR-4.md).
5. **Базы данных: PostgreSQL + работа без ORM** — тема опирается на параллельный курс «SQL. Начальный курс»: сам язык запросов не повторяется, разбирается всё, что вокруг него. Как HTTP-запрос от фронтенда проходит через слои сервера и превращается в запрос к базе и обратно в JSON: проектирование схемы (в том числе обязательно таблица пользователей — карточки должны иметь владельца с самого начала), простые SQL-скрипты для схемы (без инструмента миграций — сложность здесь не нужна), `node-postgres` (`pg`) и пул соединений, параметризованные запросы, сборка условий `WHERE` из фильтров, пришедших в строке запроса, четвёртый слой (репозиторий) и перевод «строка таблицы ↔ объект приложения», соответствие ответа базы статус-коду ответа API, проблема N+1 и её лечение через `JOIN`. Материалы: [лекция](5-PostgreSQL/LECTURE-5.md) · [семинар](5-PostgreSQL/SEMINAR-5.md).
6. **Аутентификация, авторизация и безопасность** — JWT, хэширование паролей, сессии vs токены, ролевой доступ — всё это уже строится поверх реальной таблицы пользователей из темы 5, а не поверх моков; база по CORS/XSS/CSRF/SQL-инъекциям и то, как параметризованные запросы (через `pg`) защищают от инъекций, вынесена в необязательный раздел лекции — для желающих углубиться, вне обязательной программы и теста. Материалы: [лекция](6-Auth-Security/LECTURE-6.md) · [семинар](6-Auth-Security/SEMINAR-6.md).
7. **Тестирование и проверка API** — виды тестирования от смоука до e2e и место каждого в пирамиде; ручная проверка запросов через Insomnia (коллекции, окружения, cookie, прогон коллекции) — на уровне «пользоваться», проверки внутри коллекции студент не пишет; автотесты на Vitest: юнит-тест чистой функции и, как основная работа темы, тесты эндпоинтов через supertest — включая правила доступа из темы 6; отдельная тестовая база и известное состояние перед каждым тестом; сценарий пользования как цепочка HTTP-запросов — вместо браузерного e2e, который в курс не входит (Cypress и Playwright упомянуты в дополнительных материалах). Материалы: [лекция](7-Testing/LECTURE-7.md) · [семинар](7-Testing/SEMINAR-7.md).
8. **Сборка и упаковка приложения** — от уже знакомого `npm run dev` к `npm run build`, что происходит при продакшн-сборке, упаковка backend и frontend в Docker-контейнер (базовый Dockerfile, без оркестрации).

**Логика проектов.** Сквозной проект семинаров — канбан-доска (доски/колонки/карточки), клиент выдаётся частично готовым. Домашнее задание — **отдельный проект: микроблог** (пользователи → посты → комментарии), структурно похожий на канбан, но из другого, повседневно знакомого домена. Это чистое API без UI, реализуемое **по выданной спецификации** (эндпоинты, формы запросов/ответов, статус-коды) — как по ТЗ в боевой разработке. Приёмка — прогон Insomnia-коллекции с автотестами; коллекция выдаётся студентам вместе со спецификацией, так что самопроверка (`inso`) доступна в любой момент до сдачи. Оба этапа ДЗ обязательно требуют использования AI-агента как части рабочего процесса (промпт-инжиниринг, ревью и осмысленная правка сгенерированного кода — с этим студенты уже знакомы по теме 2):

- **ДЗ, этап 1 — CRUD без авторизации** (после темы 5, к субботе 10): backend микроблога на Express + PostgreSQL через `pg` по выданной спецификации: пользователи, посты, комментарии, связи между ними. Полноценной аутентификации ещё нет — автор указывается полем `author_id` в запросе, без проверки личности. Приёмка: Insomnia-коллекция этапа 1 проходит целиком. В отчёте студент указывает, какие части делал с помощью AI-агента и как проверял сгенерированный код.
- **ДЗ, этап 2 — авторизация и тестирование** (выдаётся сразу после темы 7, к субботе 14; дополняет этап 1): настоящая аутентификация/авторизация поверх кода этапа 1 (JWT, роли — по материалу темы 6): чтение постов — публичное, без токена; создание постов и комментариев — только аутентифицированным; правка и удаление поста — только его автор; удаление чужих комментариев — модератор. Плюс покрытие получившегося кода тестами эндпоинтов (Vitest + supertest — по материалу темы 7). Приёмка: Insomnia-коллекция этапа 2 + ревью тестов. Срок сдачи — через 1–2 недели после субботы 16, до экзамена. Тот же отчёт по использованию AI-агента, что и на этапе 1.

> Полная спецификация API микроблога и Insomnia-коллекция публикуются отдельным документом — после готовности конспектов и семинаров по всем темам курса.

> Упаковка в Docker (`npm run build` + Dockerfile, тема 8) больше не входит в состав домашних заданий — переносится в итоговое оценочное задание семинара по теме 8 (без отдельного дедлайна после конца курса), это и снимает проблему нехватки времени на ДЗ после темы 8.
